# ADR-004 · 判定枚举三值，禁用「不符合/淘汰」类措辞

- **状态**：已采纳
- **日期**：2026-10-22
- **相关**：计划书 §4.4、§5.5、§8.3 检查 C-1/C-2

## 背景

HR 侧输出最容易滑向的地方是**判定措辞**。
一个「基本符合」的判断，写成「勉强符合」读起来完全一样，
但写成一个带否决意味的词，性质就变了。

更麻烦的是中文的语义漂移：
「不合适」在日常语境里可能只是「不太匹配」，
但在招聘工具里会被读成淘汰结论。

## 备选方案

| 方案 | 枚举 | 问题 |
|---|---|---|
| A. 二值 | 通过 / 不通过 | 丢失「有相邻经验」这个最常见也最有信息量的中间态 |
| B. 三值但用负面措辞 | 符合 / 基本符合 / 不符合 | 「不符合」= 淘汰结论，越界 |
| C. **三值且全部中性** | demonstrated / adjacent / not_evidenced | 需要教育用户理解第三个值 |

## 决策

采用 **C**。

| 值 | 含义 | 中文展示 | 禁止的近义说法 |
|---|---|---|---|
| `demonstrated` | 有直接证据支持该能力达到要求层级 | 已体现 | ~~符合/通过/胜任~~ |
| `adjacent` | 有相邻经验，部分满足 | 有相邻经验 | ~~基本符合/勉强~~ |
| `not_evidenced` | 本次提问未获得证据 | 本次未获取到证据 | ~~不符合/不合格/淘汰~~ |

三处必须一致：**代码常量、prompt、UI 文案、文档**。
`VERDICT_LABELS` 是唯一来源，前端 `verdictLabel()` 直接对应。

**`not_evidenced` ≠ 不适合** —— 这是整个设计的核心区分：

> 简历没写 ≠ 不会。HR 侧的作用恰恰是**找出哪些地方还没问到**，
> 而不是替面试官下结论。

## 强制手段

| # | 手段 | 位置 |
|---|---|---|
| 1 | 枚举白名单 + 运行期断言 | `assert_allowed_verdict()` |
| 2 | 禁用词清单 | `FORBIDDEN_TERMS` |
| 3 | 全仓扫描脚本 | `scripts/check_forbidden_terms.py` |
| 4 | 单元测试穷举 | `test_verdict_only_three_values` |

## 代价

- 「本次未获取到证据」比「不符合」啰嗦，需要用户教育。
- 禁用词是黑名单，永远可能漏词。缓解办法是：
  枚举白名单（白名单机制天然覆盖黑名单漏词的场景）为主，
  黑名单只作为额外防线。

## 什么条件下推翻它

不推翻。若未来要引入「岗位匹配度总分」这类聚合指标，
它必须由三值枚举**推导**出来，而不是让模型直接给分 ——
否则等于开了一个绕过枚举的越界通道。
